# 商策 · 商家运营工作台

> **本项目中的数据和信息仅用于作品展示，不是真实业务数据。** 商家、店铺名称、商品、人员身份、经营指标、活动规则、阈值、截止时间、触达内容和回执均为虚构或合成信息，不来自真实商家、用户或企业内部系统，也不代表任何平台的官方政策。请勿据此开展实际经营、收费或消息发送。

[在线体验](https://toxictilltheend.github.io/merchant-ops-copilot/)

这是一个可交互的商家运营产品原型，使用暖橙色界面，展示“查看经营资料 → 识别缺口 → 编排核对事项 → 审核话术和名单 → 模拟触达 → 记录回执 → 复盘跟进”的完整过程。小策是规则驱动的演示助手，没有接入真实大模型、消息渠道或企业后台。

## 三分钟体验

1. 点击顶部「三分钟体验」，选择「活动提醒」。助手给出消费券缺口名单，同时显示范围、筛选条件、数据来源和规则版本。
2. 在待办编排中核对商家和任务，点击「批量触达」，修改话术、渠道或发送时间。选择「文字+商家诊断日报」可以查看商家端预览。
3. 点击提交，先查看审核页中的候选、可提交和排除名单；确认后才创建本地任务。所有提交均为模拟操作。
4. 在「草稿与任务」逐步模拟发送、送达、回复或行动完成；也可以标记失败并重试。打开复盘，核对尚未完成的商家。
5. 「缺失资料」展示未知值不当作零的处理方式；「重复触达拦截」用临时样本演示换话术、换渠道仍会受频控限制，且不会增加已保存的任务。

## 已实现的功能

| 模块 | 可体验内容 |
| --- | --- |
| 工作空间 | 常用入口和联系人管理、待办新增和完成状态、本地协作事项保存 |
| 角色与范围 | 管理员64家、行业负责人8家、原创设计赛道6家、产业带赛道2家、当前专员6家；切换身份/行业会清空未提交名单，保留已保存记录 |
| 统一经营模型 | 8个行业、64家合成商家、唯一商家ID与商品ID；看板、行业和专员进度、异常名单、诊断、预览、回执均关联同一商家表 |
| 商家筛选 | ID、店铺名称、健康度、规模、层级、待办类型、异常原因、建联与认领状态；跨页勾选、列展示控制 |
| 规则助手 | 查询消费券、红包、前N、素材、报名、上新、直播和成交下滑；给出筛选条件和资料来源；不能识别的问题或未提供的费率明确说明资料不足 |
| 任务编排 | 一家商家的多项核对合并，支持模板、话术编辑、渠道选择、商家端预览、草稿保存恢复 |
| 名单文件 | 在浏览器读取 `.xlsx` / `.xls` / `.csv`；按当前候选范围匹配，按商家ID去重，过滤范围外记录；文件最多5 MB、5000行；错误文件不会覆盖原名单 |
| 提交审核 | 显示候选、可提交、排除及原因；审批绑定名单、任务映射、话术、渠道、时间和规则版本；发生变化必须重新审核 |
| 触达频控 | 同活动同商家24小时冷却，滚动7天最多2次，跨渠道合并；已行动商家停止提醒；待执行任务预占收件人，不能另建任务绕过 |
| 活动规则 | 展示适用条件、截止日、来源、版本；演示V1/V2阈值变化；规则变更暂停定时任务，重新核对后再提交 |
| 定时任务 | 以北京时间校验未来时间和活动截止日；支持修改、重新审核、取消、到期手动模拟执行 |
| 状态与失败处理 | 已提交 → 已发送 → 已送达 → 已读/已回复 → 已行动；明确失败原因，仅重试失败收件人，最多3次尝试，保留事件记录 |
| 触达中心 | 按日期、行业、专员、活动、渠道及状态筛选；同一范围、日期和活动口径计算分母分子，按商家ID去重；支持任务明细导出 |
| 复盘跟进 | 汇总未行动、未回复和失败原因，排除已完成商家；再次跟进仍检查冷却和次数限制，不根据演示数据宣称经营收益 |
| 本地记录 | 草稿、模板、入口、待办、任务、审批和回执保存在当前浏览器；确认后才能重置，重置可先导出 |

## 数据、统计和演示规则

- **SYN-MERCHANTS-01**：统一的合成商家及商品快照。经营指标只展示当前合成快照，不伪造用户所选日期的历史趋势；触达中心可按实际模拟记录日期筛选。
- **SYN-POLICY-01**：本作品自拟的活动条件、阈值和频控。V1阈值60%，V2阈值70%；截止日由演示初始化日向后14天生成，不对应任何真实活动。
- **SYN-RECEIPTS-01**：与统一商家ID关联的预置合成历史回执，与体验者创建的本地任务明确区分。样例会参与演示频控。
- 率类经营指标对有数据商家取算术平均，数量类求和；不是GMV加权结果。缺失素材字段标为「待核对」，从该字段的平均分母和自动异常名单中排除。
- 创建时间保存为标准时间戳，显示、业务日和计划校验使用 `Asia/Shanghai`（北京时间），与体验者设备时区无关。
- 提交后冻结商家指标、生成话术、任务映射和规则版本。后续规则变化不会改写已经创建的发送快照。
- 导出文件包含“合成展示，不是真实业务数据”标记。表格以公式控制字符开头的文本按普通文本导出。

## 使用边界

**这是可交互的前端演示原型，不是可直接投入生产的商家运营系统。**

- 助手基于字段和明确规则工作，没有真实模型推理、RAG或外部政策检索；不会生成没有依据的收费或经营结论。
- 所有发送、送达、失败和行动状态由体验者手动模拟，不会联系任何真实商家。定时任务只在页面中保存并手动执行；关闭页面后没有后台调度。周期提醒需要逐次核对，不自动循环发送。
- 身份切换用于展示可见范围和产品规则，没有真实账号登录或服务器鉴权。源文件中的示例数据属于公开可见的演示素材。
- 数据只存在当前浏览器，没有后端数据库、跨设备同步、多人协作锁或服务端幂等保障。清除浏览器数据、无痕模式退出、设备更换可能丢失体验记录，请按需导出。
- 名单文件在浏览器本地解析，不会由本作品上传到服务器。仍建议只导入虚构资料，不要在公开演示中录入真实客户信息。
- 预置样例和用户操作不是业务效果评估数据，不能作为真实ROI、转化提升或客户规模的证据。

## 本地运行与结构

本目录为纯静态网页，没有安装依赖或构建步骤。使用任意本地静态服务器打开本目录的 `index.html`，或直接打开在线体验链接。使用HTTP静态服务有助于得到稳定的本地存储行为。

```text
index.html                 页面和演示入口
styles/base.css            基础布局
styles/theme.css           暖橙配色、响应式和任务状态样式
js/reference.js            原工作空间交互兼容层
js/business.js             统一合成数据、统计、范围、时间、频控和状态规则
js/records.js              浏览器持久化、Excel读写和基础记录界面
js/enhancements.js         原有交互兼容补齐
js/upgrade.js              将页面和助手接入统一模型、审核与业务闭环
vendor/                    本地表格处理库及许可证
```

表格处理使用本地打包的 SheetJS Community Edition 0.20.3，许可见 `vendor/LICENSE-SheetJS.txt`。页面不依赖在线模型服务或消息供应商。

## 检查与版本兼容

升级前保存版本快照，40项原有检查通过。升级后112项检查通过（34项业务模型、78项浏览器交互），覆盖1600 / 1280 / 390宽度；覆盖数据一致性、角色收窄、字段缺失、跨渠道频控、审批失效、定时任务、取消、失败重试、复盘、Excel、刷新恢复和移动端布局。
